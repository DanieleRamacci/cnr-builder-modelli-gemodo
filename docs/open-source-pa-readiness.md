# Readiness Open Source E Riuso PA

Questa pagina raccoglie i requisiti documentali per rendere GEMODO pubblicabile,
ispezionabile e riusabile da altre pubbliche amministrazioni.

## Stato

La readiness e' in preparazione. La licenza definitiva e' `DA_CONFERMARE` prima della
pubblicazione pubblica.

## Checklist Minima

- README con percorso chiaro verso documentazione navigabile.
- Licenza open source confermata.
- Guida setup da zero.
- Guida sviluppo locale.
- Guida installazione/deployment produzione.
- Architettura e confini GEBAN/GEMODO/documentale.
- Configurazione ambiente e variabili principali.
- Sicurezza, JWT/OIDC, ruoli, claim e autorizzazioni applicative.
- API documentation con OpenAPI, Swagger/ReDoc, esempi e catalogo errori.
- Guida test e verifica qualita'.
- Contributing guide.
- Security policy per segnalare vulnerabilita'.
- Changelog e note di release.
- Verifica assenza di secret, token, credenziali, dati personali reali e URL sensibili.

## Principi Di Pubblicazione

- La documentazione deve essere in formato testuale versionabile.
- Gli esempi devono usare solo dati demo.
- Le istruzioni non devono dipendere da conoscenza implicita del team.
- Le decisioni aperte devono essere tracciate con owner e fase bloccante.
- I contratti API devono essere leggibili senza consultare il codice sorgente.
